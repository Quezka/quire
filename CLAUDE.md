# Quire

Python 3.10+ / PySide6 desktop app (Linux + Windows). Clean Architecture; see README "Architecture".

- The look (theme, icons, translation core, UI scale, dialog fitting, Enter-leaves-the-box, page widgets) comes from the shared `quezka-ui` package (`../suite-kit`); `presentation/theme.py`, `icons.py`, `i18n.py`, `uiscale.py`, `fit.py`, `leave_on_enter.py` are aliases to it. Change those in the kit, not here; this app keeps its catalogues (`locales/`), Quire-only widgets (`widgets.py`, `views/common.py` extras) and its icon.
- Layers: `quire/domain` → `quire/application` → `quire/infrastructure` + `quire/presentation`; wired in `quire/bootstrap.py`.
- Dependency rule is enforced by `tests/test_architecture.py`; never import PySide6/sqlite3 into domain or application, never import infrastructure into presentation.
- Run: `.venv/bin/quire --demo`. Test: `.venv/bin/python -m pytest -q`.
- Headless UI checks: `QT_QPA_PLATFORM=offscreen`.
- Dates in format strings: don't use `%-d` (breaks on Windows); build day numbers with `d.day`.
- School sync: `SchoolSyncService.fetch()` is network-only and runs on a worker thread; `apply()` writes to SQLite and must run on the UI thread (sqlite connections are thread-bound).
- Device sync: `SyncService.prepare()`/`finish()` run on the UI thread, `exchange()` (network) on a worker. Change tracking is SQLite triggers in `infrastructure/sync_store.py` (uid/modified/dirty columns, tombstones, `sync_flags` switch). A new synced table or column needs its export/upsert there. Tests use `tests/fakes.FakeCloud` and in-memory sign-in storage, never Firebase or the real keyring.
- Sync backends: `CloudConfig.backend` is `firebase` or `server`. `infrastructure/cloud.RoutingCloud` sends each call to `FirebaseCloud` or `QuireServerCloud` (`infrastructure/quire_server.py`, the self-hosted quire-server; for it `project_id` is the server address and `api_key` is unused). The phone has the same split (`sync/RoutingCloud.kt`, `sync/QuireServer.kt`); `Backends` holds the names. Moving to another backend or address marks everything dirty (`SyncStore.mark_all_dirty`, `Records.markAllDirty`) so the new place gets all data. `quire-link:` is version 1 for Firebase, version 2 (`backend`, `url`) for a server. The protocol is `quire-server/docs/PROTOCOL.md`; `tests/test_quire_server.py` and `QuireServerCloudTest.kt` mirror its `tests/reference_client.py`.
- Splash: `presentation/splash.py` (`SplashScreen`) is shown by `app.main()` before the database opens (skip with `--no-splash`, `QUIRE_NO_SPLASH=1`, or `--background`); `qt_app.run()` advances it and calls `finish()` once the window is up. New start-up steps need translated status strings.
- Self-update: `UpdateService` (ports `ReleaseFeed`, `UpdateInstaller`) with `infrastructure/updates.py` (GitHub releases API, `DebInstaller` via pkexec apt, `WindowsSetupInstaller` running the Inno setup with /SILENT; `packaging/quire.iss` restarts Quire after a silent install). Asset names must stay `quire_<v>_<arch>.deb` and `Quire-<v>-windows-x64-setup.exe`. Tests use `FakeReleases`/`FakeInstaller`, never GitHub.
- Android app: `android/` (Kotlin + Compose, minSdk 26). It reads and writes sync records in the desktop's payload format (`data/Codec.kt` mirrors `infrastructure/sync_store.py`). If you change a payload on either side, regenerate `android/app/src/test/resources/desktop_records.json` and run both test suites. Local toolchain: `~/.local/share/android-dev` (JDK 17, SDK, Gradle); run `JAVA_HOME=~/.local/share/android-dev/jdk17 ANDROID_HOME=~/.local/share/android-dev/sdk ./gradlew testDebugUnitTest`, and add `SCREENSHOTS=1` to render screens to `app/build/screenshots`. The release key is in `~/.local/share/quire-signing` and in the repo secrets `QUIRE_KEYSTORE_B64`/`QUIRE_KEYSTORE_PASSWORD`.
- Bedside provider: `bedside/BedsideProvider.kt` feeds the Vesper clock app on the same phone (contract in `docs/bedside.md`, rules in `domain/Bedside.kt`); it is read-only, behind a runtime permission, and never exposes school data. Vesper mirrors the contract, so change both together.
- Android structure: `domain/` (pure Kotlin rules mirroring the desktop's: Agenda, Work, Focus, Register, Markdown), `data/` (records, Codec, Repository), `sync/`, `school/` (Classeviva adapter, SchoolSync, encrypted password via `KeystoreBox`), `notify/` (reminders via AlarmManager, notifications), `focus/`, `ocr/` (Tesseract; models in `assets/tessdata`, JitPack dependency limited to `cz.adaptech.*`), `update/`, `ui/`. Wiring is in `QuireApp.kt` (`Container`). New UI text goes in `res/values*/strings_more.xml` (English, Russian and Italian).
- Phone setup code: the desktop's `SyncService.phone_link()` makes `quire-link:<base64url JSON>` (shown as a QR code with `segno`); the phone parses it in `sync/DeviceLink.kt`. Keep both sides in step.
- Classeviva is an unofficial API (`quire/infrastructure/classeviva.py`); tests use canned JSON (`tests/test_classeviva.py`) and `tests/fakes.FakeRegister`, never the network. Schools may record a late entry or early exit without an hour (`evtHPos: null`, "ora -1" on the website); the student can enter it (`Absence.own_hour`), and it's kept across syncs.
- Pictures in notes: `NoteImage` (domain), table `note_images`, synced as kind `image` (`{"mime", "data": base64}`, before notes), referenced in Markdown as `![alt](quire-image:<uid>)`. Max 700 KB each (Firestore's 1 MiB per document); `firebase._batches` keeps commits under the request size. The UI side is `presentation/note_images.py` (paste/drop, `load_picture`, `note_pdf`). Ligature PNGs carry their diagram in a `zTXt` "ligature" chunk: keep pasted PNGs byte for byte. "Edit in Ligature" is `infrastructure/ligature.LigatureApp` (finds `ligature` on PATH, or Windows App Paths), and the notes view watches the file (Ligature saves by replacing it). The phone shows pictures in the note preview (`Codec.image`, `MarkdownPreview(image=)`).
- Notes editor: `presentation/note_editor.py` (`NoteEditor`, a QTextEdit you type into formatted). Markdown maps line by line onto blocks (`load_markdown` / `document_markdown`), not through Qt's Markdown importer (it joins lines, hard-wraps at 80 columns, and leaks checkbox markers). Round trips must stay exact: `tests/test_note_editor.py`. The phone does the same with `domain/NoteBlocks.kt` (parse/write, and the Enter/Backspace/shortcut rules) and `ui/BlockEditor.kt` (one BasicTextField per line; the focused line shows faded marks, the others hide them via an OffsetMapping); keep both apps' line rules in step (`NoteBlocksTest`, `BlockEditorStateTest`).
- Schema changes: bump `SCHEMA_VERSION` in `infrastructure/sqlite.py` and add an idempotent step in `_migrate()`; cover it in `tests/test_migration.py`.
- Never name a Qt subclass attribute after a Qt method (e.g. `self.done` on a QDialog); UI smoke tests in `tests/test_ui_smoke.py` catch these.
- UI text must be translatable: wrap it in `_()` (or `N_()`/`C_()`), add the Russian and Italian to `quire/presentation/locales/ru.py` and `it.py`; `tests/test_i18n.py` enforces it. Never format dates with strftime names; use the i18n name helpers.
- Job pay: `domain/payroll.py` (pure: monthly/hourly gross, INPS, IRPEF with the work detrazione prorated by days, tredicesima/quattordicesima, TFR, cuneo bonus; a year is worked out whole, then spread over months) is mirrored line for line by the phone's `domain/Payroll.kt`; keep `tests/test_payroll.py` and `PayrollTest` on the same numbers. `WorkService.payslips()` / `Work.payslips()` feed the Payslips dialog.
- Medicines (`domain/medicine.py`, kinds `medicine` and `dose`) sync like water; the phone mirrors them in `domain/Medicine.kt`, `Codec` and `Repository`. Money (kind `money`, table `transactions`, job payday) was removed 2026-11-14 (user uses Revolut): table and columns stay in the schema, nothing reads or syncs them. All-day events are events from 00:00 to 24:00 (no new field, like milestones are one minute long).
- System calendar: `domain/ical.py` writes the file, `CalendarService` decides, `infrastructure/system_calendar.py` puts it where the system reads it (Linux: an Evolution Data Server source, `quire-agenda.source`, read-only; Windows: imported by opening it). One way only. Only touches anything once the user switches it on.
- The phone's palette (`ui/Theme.kt`) is the kit's (`quezka_ui/theme.py`) token for token, as are Cadence's and Vesper's: change them together. The widget alone takes the system's colours on Android 12+, on purpose.
- Look (0.47+): Material 3 tonal, no glass (user, 2026-11-14). Phone bars are solid (`ui/Glass.kt` keeps the `GlassScreen` layout, `Modifier.glass` = solid background); desktop from the kit. Never a gradient wash or colour blobs.
- The Material 3 look and the Manrope font come from the kit (`theme.material`, `fonts.py`); so does the trackpad glide (`kinetic.py`). In Qt a `border-radius` bigger than half the widget's height is ignored and the widget goes square, so keep button radii at 12 px or below.
- Assistant (0.48, ADHD-friendly; user wants to live "using pretty much only Quire"): phone `notify/AssistantManager.kt` (now/next ongoing notif on the lock screen, morning/evening digest, afternoon nudge, hub batches; Settings › Assistant) and `notify/Hub.kt` (`HubListener`, NotificationListenerService: other apps' notifs held for the digest, rule per app pass/hold/mute, calls/alarms pass). Rules in `domain/Assistant.kt`. One notif channel per kind with its own icon (`res/drawable/ic_n_*`, from the kit's Material Symbols). Today's "one thing now" card on both apps (`ui/TodayScreen.kt` NowCard, `presentation/views/now_card.py`); `TaskService.next_step()` / `Assistant.nextStep`.
- Ideas (0.48): kind `idea`, table `ideas` (schema v20), desktop page and phone screen (More), in the evening digest.
- Focus blocks (0.48): `plan_block` / `planBlock`, `PomodoroTimer.start_block`; a finished or stopped block becomes an Event ("Focus: <task>").
